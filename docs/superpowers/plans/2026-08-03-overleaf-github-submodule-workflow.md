# Overleaf--GitHub Dissertation Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the local dissertation area into a versioned Overleaf review workspace whose working manuscript is a Git submodule, while preserving the initial export and keeping Overleaf as the only normal source editor.

**Architecture:** The dedicated private dissertation repository is mounted at `dissertation/manuscript/` as a Git submodule. The parent repository stores review checklists and milestone release artifacts, while the submodule is pull-only during normal operation. The current extracted source tree remains available until its contents have been compared with the submodule, then moves outside the parent working tree as a safety backup.

**Tech Stack:** Git submodules, Overleaf GitHub Sync, POSIX shell tools, SHA-256, Poppler `pdfinfo`, ZIP integrity checks, Markdown, JSON.

## Global Constraints

- Overleaf is the only normal editing surface for dissertation `.tex`, `.bib`, and paper-facing figure files.
- Do not modify or push files inside `dissertation/manuscript/` during this implementation.
- Do not use the raw `git.overleaf.com` remote alongside GitHub Sync.
- Preserve the current ZIP, PDF, two compile-log screenshots, literature PDFs, and `evidence_audit.md`.
- Do not stage or commit unrelated P3 documents, `tmp/`, literature PDFs ignored by the parent repository, or other user work.
- Do not force-push, reset, rewrite history, or delete an unverified source copy.
- The expected dissertation repository is `https://github.com/Crises-Strity/UCL-Final-Dissertation.git` on branch `main`.
- The expected initial dissertation commit is `d05b6c86b8ced810ac47d9ed96bb73b6eba7db36`.
- Local LaTeX compilation is outside scope; Overleaf remains the compiler.

- [x] **Step 1: Create the dissertation workflow README**

Use `apply_patch` to create `dissertation/README.md` with these sections and exact rules:

```markdown
# Dissertation workflow

## Source of truth

Overleaf is the only normal editor for files in `manuscript/`. GitHub Sync carries completed Overleaf checkpoints to `Crises-Strity/UCL-Final-Dissertation`; this parent repository records the reviewed submodule commit.

Do not edit the manuscript locally, on the GitHub web interface, or through the raw `git.overleaf.com` remote during the normal workflow.

## Routine update

1. Finish the edit and compile in Overleaf.
2. Push Overleaf changes to GitHub with a meaningful message.
3. Confirm that the local submodule is clean.
4. Fast-forward the submodule from GitHub.
5. Run local source, evidence, citation, and PDF checks.
6. Record findings under `reviews/`.
7. Commit the review and updated submodule pointer in the parent repository.
8. Apply accepted changes in Overleaf.

```bash
git -C dissertation/manuscript status --short
git -C dissertation/manuscript pull --ff-only origin main
git add dissertation/manuscript dissertation/reviews
git commit -m "docs: review dissertation checkpoint YYYY-MM-DD"
```

## Stop conditions

Stop without resetting or force-pushing if the submodule is dirty, a pull is not fast-forward, GitHub contains an unexpected commit, or a release ZIP differs from the corresponding dissertation commit.

## Release checkpoint

Milestone releases live under `releases/YYYY-MM-DD-label/` and contain the Overleaf source ZIP, compiled PDF, full compile log when available (otherwise complete screenshots), and a manifest with SHA-256 hashes, page count, compiler, dissertation commit, and review status.

## Editing-authority exception

A local manuscript edit requires an explicit Overleaf freeze and user authorization. After the local change is reviewed and synchronized through GitHub, Overleaf must pull it, compile it, and be explicitly restored as the authoritative editor.
```
